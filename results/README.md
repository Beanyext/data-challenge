# Результаты для сдачи

Команда: **seeusoon**. Формат взят из `CQA_Student_Guide_Appendix_Results.pdf`.

- DEV: `results/dev/results.json`, 65 записей: 60 чатов и 5 звонков.
- PROD: `results/prod/results.json`, 10 контрольных чатов.

Файлы `results.json` появятся после обработки настоящих диалогов. Демонстрационных ответов в этой папке нет.

## Подготовка через интерфейс

1. Запустите общий React-интерфейс по [web/README.md](../web/README.md) и откройте раздел **Выгрузка**. Подготовка из файлов работает без сервера, в том числе при явно включённом учебном режиме приложения. Учебные оценки в итоговый файл не допускаются.
2. Выберите DEV или PROD и исходный JSON соответствующего набора организаторов. Поддерживаются массив записей, `{records:[...]}` и обёртка `{data:{records:[...]}}`.
3. Выберите сохранённые JSON-файлы оценщика из `outputs/eval/<запуск>/` или сервер команды. Можно загрузить отдельные файлы сразу вместе с `summary.json`: сводка пропускается. Готовый файл сдачи не принимается как исходная оценка, чтобы не сдвинуть номера реплик повторно.
4. Проверьте фактический режим и название модели. Интерфейс подставляет доступные сведения из оценок, включая резервные вызовы; ручные значения сохраняются. Имена всех использованных моделей должны присутствовать в общем названии. По умолчанию экспортируются исходные ответы AI. Служебные `original_answer`, равные текущим ответам без ручного решения, не означают пересмотр. После решения проверяющего для исходной версии нужен полный `original_criteria`, включая исходные доказательства; иначе нужно явно выбрать финальную версию. Регламент отдельно не уточняет выбор после пересмотра.
5. Нажмите **Проверить результаты**. Исправьте блокирующие ошибки. Изучите предупреждения и записи `status: "error"` и подтвердите их отдельным флажком, если они есть. Скачайте `results.json` и сохраните по пути выбранного набора выше. Любая правка полей или замена файлов требует новой проверки.

Исходный JSON организаторов определяет полный набор ID и исходную нумерацию реплик. Файлы читаются строго как UTF-8, BOM допустим. Ограничения: до 20 МБ на файл, до 200 файлов оценок и 50 МБ оценок суммарно. Серверный источник собирает сохранённые результаты только через GET и требует рабочего API; неверное подключение не подменяется учебными данными. Переключение RU / EN / KK и переход между разделами не сбрасывают выбранные файлы и подготовленный результат; перезагрузка браузера их не восстанавливает.

Экспорт читает сохранённые данные, не запускает модель, не записывает файл в репозиторий и не публикует результаты. Файлы исходного набора и оценщика не сохраняются в localStorage. Учебное или mock-происхождение блокируется даже у записи с ошибкой обработки. Не коммитьте исходные транскрипты и подписанные ссылки API организаторов. Перед публикацией проверьте обоснования: в них не должно быть персональных данных. Очевидные адреса почты, телефоны и 12-значные идентификаторы дают предупреждение; это не полное автоматическое обезличивание.

## Проверка файла перед commit

Для CLI-проверки нужен Node.js. Из корня репозитория, указав путь к исходному JSON **вне git**:

```bash
node web/check-submission.mjs --dataset dev --source /path/to/original-dev.json --input results/dev/results.json
node web/check-submission.mjs --dataset prod --source /path/to/original-prod.json --input results/prod/results.json
```

Команда только читает файлы. Код завершения: `0` — формат корректен, `1` — ошибка схемы или несоответствие набору, `2` — аргументы, чтение или JSON. Записи `status: "error"` допустимы по регламенту и выводятся как предупреждение; успешная проверка формата не означает высокую точность AI.

Проверяются исходные ID, отсутствие дублей и пропусков, восемь канонических критериев, типы `boolean` / `number` / `null`, допустимые шкалы и N/A, ссылки на исходные реплики с **1**, итоговый балл и отдельный флаг грубой ошибки. Ошибка обработки остаётся отдельной записью с `criteria: []` и `score: null`. Учебные и mock-оценки блокируются при подготовке; CLI не может установить происхождение уже вручную переписанного файла.

После проверки организаторы требуют commit и push обоих файлов в открытый репозиторий до стоп-кода (старт + 24 часа). Контрольный набор выдаётся на старте + 23 часа. Публикацию выполняет команда; создание интерфейса выгрузки само по себе результаты не сдаёт. Проверки интерфейса и API проводились без платного AI; точность относительно Ground Truth пока не измерена. Подробности — в [web/QA.md](../web/QA.md).
