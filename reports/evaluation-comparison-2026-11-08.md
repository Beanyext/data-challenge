# Сравнение двух сохранённых оценок

08.11.2026, до стоп-кода по Asia/Almaty. Ветка `bekmurat/work`, исходный коммит `a358ea4`. Изменения этой задачи не закоммичены и не запушены.

## Что сделано и польза

В карточке диалога, внутри «История оценок», добавлен раздел сравнения двух завершённых запусков одной версии чек-листа. Запуск выбирается по дате, модели, версии и короткому ID; полный ID виден под полем. Сравнение загружается только после явного действия пользователя.

Рядом показаны сохранённые итоги, ответы, баллы/максимумы, обоснования, причины N/A и пересмотра, исходные реплики-доказательства и цитаты в оценке. Нумерация реплик начинается с 1. Для отсутствующей оценки ответа выводится явное сообщение, ноль не подставляется. Показаны число изменённых критериев и разница сохранённых итогов. Фильтр «Только изменения» учитывает изменения объяснений и доказательств даже при одинаковых ответах.

Это помогает проверяющему объяснить расхождения и показать жюри, какие именно решения изменились. Рост балла не объявляется ростом точности. Исторические данные и текущая оценка не меняются.

Проверяется точный ID каждого запрошенного запуска, принадлежность диалогу, версия и сохранённые правила. Сравнение разных версий недоступно; несовместимые снимки одной версии также отклоняются. Для неполной оценки разница итогов не вычисляется. Критерий грубой ошибки может быть `applicable:false`, поскольку он не входит в сумму: его допустимый yes/no всё равно считается полным ответом.

Все новые надписи RU/EN/KK. Смена языка сохраняет выбранную пару, загруженные результаты и фильтр. На узком экране колонки располагаются друг под другом. Запросов оценки или записи нет, используются только существующие GET. Защищённые модули, серверный код и зависимости не менялись.

## Отдельная находка вне задачи

В существующей аналитике воспроизведён похожий дефект проверки полноты: `web/analytics.mjs` исключает из полного среднего оценку, у которой критерий грубой ошибки имеет `applicable:false`, хотя сервер возвращает `complete:true`. На синтетическом стенде для freedom-chat v1 загружены три сохранённые оценки, но `scored:0`, `average:null`. Кроме того, такой критерий попадает в unknown вместо знаменателя грубых ошибок. Это существующий код, не новый экран сравнения. По правилу минимального объёма аналитика в задаче сравнения не менялась. Затем по запросу пользователя дефект исправлен с регрессиями: см. [отчёт об исправлениях](analytics-fixes-2026-11-08.md).

## Воспроизведение нового сценария

Из корня проекта: `PYTHONUTF8=1 python -m uvicorn comparison_server:app --app-dir tests --host 127.0.0.1 --port 8767`. Стенд создаёт временную базу и только вымышленные mock-оценки. Затем выполнить функцию `web/tests/browser-comparison.js` в Playwright с объектом page, как остальные браузерные сценарии проекта. Оценки для этого теста создаются локально заранее; браузер выполняет только чтение.
