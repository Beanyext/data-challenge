## Что исправлено, почему и польза

1. **Смешанные ISO-метки времени блокировали список диалогов.** Если одна реплика содержала часовой пояс, а другая нет, вычитание datetime завершалось TypeError уже после сохранения диалога. Теперь исходные метки сохраняются и безопасно отображаются; позиция аудио для несовместимых меток не вычисляется. Это сохраняет доступ к списку и позволяет обработать диалог без выдумывания часового пояса. Обычные MM:SS и согласованные ISO-метки работают по-прежнему.
2. **Ошибка API могла раскрыть подписанный адрес.** Содержимое upstream error с URL/данными доступа больше не попадает в DataApiError и HTTP-ответ. Использована уже существующая надпись с RU/EN/KK-переводами. Безопасная краткая причина ошибки по-прежнему сохраняется.
3. **Нельзя было задать код нового критерия через интерфейс.** Добавлены поле «Код для выгрузки», серверные ограничения формата и уникальности, учёт изменения кода в сравнении «Было / Станет». Надписи сразу RU/EN/KK. Жюри может задать новый критерий и его код через UI, без правки исходного чек-листа.
4. **Нельзя было исправить отсутствующий ответ модели.** Критерий с needs_review теперь открывается проверяющему. Отсутствующий ответ нельзя подтвердить: человек должен явно выбрать допустимый ответ и написать причину. Исходная оценка сохраняется.
5. **Финальная выгрузка теряла смысл ручного пересмотра.** Для пересмотренного критерия используются слова проверяющего, а исходная выгрузка сохраняет исходное обоснование. Старые problems разрешено считать рассмотренными только при явном совпадающем решении, непустой причине и снятом needs_review. Проверки допустимого ответа, доказательств, происхождения и схемы не ослаблены.
