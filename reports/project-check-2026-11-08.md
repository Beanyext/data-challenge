## Подтверждённые ошибки, найденные и исправленные в этом проходе

1. **CLI падал на массивах/объектах вместо ID.** conversation_id и criterion_id теперь проверяются до операций с dict/set. Внешний JSON отклоняется обычной ошибкой, без traceback.
2. **Нестрогое имя модели и учебная сдача.** model.name требует непустую строку. По умолчанию build/check отказывают mock/demo. Для репетиции остаются явные `build/check --allow-mock` и `control --provider mock`; вывод помечен учебным, предложение git add/push для mock убрано. Реальные имена с внутренней подстрокой вроде mockingbird не блокируются.
3. **Ложное доказательство из bool или повреждённого диапазона.** Python считал true целым индексом1 и экспортировал реплику2. Теперь bool, неверные типы и выходящие за границы ссылки/диапазоны отклоняются; результат сохраняется явной строкой error с исходным ID. Валидный индекс0 по-прежнему становится репликой1. Ошибочные ссылки не обрезаются и не превращаются в выдуманные доказательства.
4. **Нестрогий error и лишние публичные поля.** error требует строку. Неизвестные поля на уровнях документа, модели, записей, критерия и score отклоняются. Так поле transcript или случайно добавленный ключ/URL не пройдёт проверку файла сдачи. Диагностика не повторяет имена/значения неизвестных полей.

Изменены только `app/results/check.py`, `app/results/export.py`, `app/results/__main__.py`, `tests/test_results.py`, плюс промпт и этот отчёт. Новых npm/pip-пакетов и новых UI-надписей нет. Предыдущие изменения интерфейса перечислены в отчётах сравнения и аналитики.

## Открытый риск и границы

**P2, граница аудио:** `app/server/audio.py:fresh_audio_url` передаёт URL плеера в urllib без ограничения схемы и адреса. Статическое ревью и безопасная подмена urlopen подтвердили достижение транспорта для синтетических loopback HTTP и file URL; настоящие файлы и внутренние сервисы не читались. Сетевой exploit не выполнялся. Host/Origin guards и работа на127.0.0.1 ограничивают внешний доступ, но загружаемые JSON с audio_url следует считать доверенными. Для работы с чужими JSON/сетевого развёртывания нужна отдельная политика разрешённых аудиоисточников, перенаправлений и DNS. Эту архитектурную границу не меняли без определения допустимых источников, чтобы не сломать запись организаторов. Нельзя считать полный SSRF-аудит или сетевое развёртывание проверенными.

Новых подтверждённых P0/P1 в выполненных проверках не найдено. Это не доказательство отсутствия всех возможных ошибок. Не проверялись настоящая модель, её точность относительно эталона, доступность платного API, настоящая контрольная группа и интеграция с Dynamics365. Реальные данные/gold/results не анализировались по значениям; полная история Git на секреты отдельно не аудировалась. Платные модели/API организаторов не вызывались, зависимости не обновлялись.

До PR остаётся объединение с актуальным origin/main и повтор проверок результата слияния. До официальной сдачи команда отдельно выполняет настоящий согласованный контрольный запуск и отправку; ИИ ничего не сдавал и не публиковал.
