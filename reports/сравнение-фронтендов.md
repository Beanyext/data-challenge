# Сравнение фронтендов CQA

Историческое сравнение до объединения. Текущая React-версия с обновлением `c3f18fa` описана в [react-integration.md](react-integration.md).

Проверено 7 ноября 2026 года: `bekmurat/work` (`56bee02`) и `seeuagaen/frontend-react-i18n` (`35a2243`). Общая база — `89ed4d8`. Проверка React-ветки выполнена в отдельной временной копии; рабочая ветка не переключалась.

## Рекомендация

Для текущей сдачи использовать `bekmurat/work` как функциональную основу. Из React-ветки перенести визуальную систему, локализацию RU/EN/ҚАЗ и более подробное представление результата. Полностью заменять нашу папку `web/` React-веткой сейчас не стоит: потеряются функции двух последних коммитов.

По внешнему виду React-вариант сильнее: более цельный корпоративный стиль, согласованные формы, статусы и действия. Наш вариант компактнее и удобнее при проверке доказательств и пересмотре оценки.

## Что есть в обеих ветках

Список и фильтры диалогов, карточка с транскриптом и доказательствами, запуск оценки через API, редактор критериев, апелляции, аудио и учебный режим. `api.mjs` и `demo.mjs` побайтово одинаковы между сравниваемыми ветками. Это сравнение фронтендов; точность AI и качество настоящего сервера здесь не измерялись.

## Преимущества bekmurat/work

- Выгрузка DEV/PROD по схеме 1.0, контроль исходных ID и доказательств, отдельная CLI-проверка JSON. В React-ветке этих модулей и экрана нет.
- Отдельный отчёт с печатью/PDF. В React-ветке такого маршрута нет.
- Очередь внимания: грубые ошибки, ручная проверка и открытые апелляции.
- Сводка по текущей выборке или всему набору с явным переключателем охвата. В React-варианте показатели относятся ко всему набору, а фильтры меняют таблицу.
- Предпросмотр изменений чек-листа «Было / Станет», защита сохранения и точное соответствие исторической версии.
- Исходные реплики прямо в форме пересмотра, переход к аудио и сохранение черновика при обычном переходе к полному диалогу и обратно.

## Преимущества seeuagaen/frontend-react-i18n

- RU/EN/ҚАЗ для интерфейса, форм, подсказок и доступных подписей; формат чисел зависит от локали. Содержимое исходных диалогов не переводится автоматически.
- При смене языка сохраняются фильтры, выбранные строки, редактор и открытые формы. Язык переключается через перезагрузку страницы с одноразовым черновиком в sessionStorage.
- Более последовательный корпоративный визуальный стиль.
- Подробное представление оценки: секции, исходная шкала, текущая ступень, базовый и перераспределённый вес, вклад в итог, видимая цитата-доказательство.
- Компоненты React/TypeScript, проверка типов и анимации с поддержкой reduced motion. Готовая сборка включена в git; для просмотра достаточно статического сервера.

Архитектура пока переходная: mutable state и обработчики остаются в `app.mjs`, а React обслуживает визуальный слой через roots и slots. Несколько React-root допустимы официальным API; само наличие React не делает это полной переработкой управления состоянием. См. [React createRoot](https://react.dev/reference/react-dom/client/createRoot#rendering-a-page-partially-built-with-react).

## Что подтверждено в браузере

Обе ветки проверены на одинаковых вымышленных данных в отдельных контекстах Chromium, при 1440 px и с reduced motion. Проверены ширины 320, 390, 768 и 1440: горизонтального переполнения документа не найдено. Ошибок JavaScript и внешних запросов в сценарии нет.

- После фильтра KZ в обоих вариантах остаётся одна строка. Наша сводка показывает 1, React-сводка сохраняет 6, поскольку описывает весь набор.
- В нашей форме пересмотра видны три исходные реплики; в React-форме исходного транскрипта нет, доступен переход к нему.
- Черновик решения после перехода к диалогу и обратно сохраняется в нашей ветке и теряется в React-ветке. При смене языка у React есть отдельный механизм сохранения черновиков.
- В React успешно переключены RU → EN → ҚАЗ. Английский и казахский заголовки отобразились; поиск и выделение строк сохранились.
- Подтверждён риск исторических правил: тестовый сервер отдал оценку по v1 без снимка, а в списке был только v2. React показал правило v2 и разрешил форму пересмотра; наша ветка предупредила об отсутствии исходной версии и заблокировала пересмотр. Места в React-ветке: `web/app.mjs:61` и `web/app.mjs:205`.

Визуальная проверка показала компромиссы React-варианта: подробная карточка заметно длиннее, сводка занимает больше места на телефоне, а текст грубой ошибки в таблице заменён небольшим знаком. Это стоит доработать при переносе оформления.

## Проверки сборки и ограничения

- Наша ветка: `node --test web/tests/*.test.mjs` — 90 тестов прошли.
- React-ветка: `npm run typecheck` — успешно; `npm test` — 31 тест прошёл. Количество тестов не является оценкой качества: наборы и размер сценариев различаются.
- React-зависимости установлены только в отдельную временную папку через `npm ci --ignore-scripts`. Пересобранный `web/react-ui.js` совпал по SHA-256 с файлом из ветки.
- Для проверки использован Node.js 20.9.0; README React-ветки рекомендует Node.js 22.
- Проверки API выполнялись на перехваченных GET с синтетическими данными. Организаторский API, платные модели и реальные транскрипты не использовались.

Слияние, изменение кода обеих веток и публикация в рамках сравнения не выполнялись.
