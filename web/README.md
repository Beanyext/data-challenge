# Интерфейс CQA

Общая версия интерфейса на React и TypeScript: экраны и формы написаны на JSX, приложение запускается через один `createRoot`. Сборщик выпускает обычный JavaScript для статического HTTP-сервера. Внешние шрифты и трекеры не используются. Визуальный ориентир — Freedom Bank; интерфейс обозначен как прототип команды.

## Локальный запуск

Собранный `react-ui.js` включён в репозиторий. Для просмотра Node.js не требуется. Из корня репозитория:

```bash
python3 -m http.server 8765 --bind 127.0.0.1 --directory web
```

Открыть `http://127.0.0.1:8765/?demo=1` для учебного примера. Открытие `index.html` через `file://` не поддерживается: модулям JavaScript нужен HTTP.

Для изменения исходников нужен Node.js с npm. После правок выполнить из корня:

```bash
npm ci --ignore-scripts --no-audit --no-fund
npm run build
npm run typecheck
npm test
python3 -m http.server 8765 --bind 127.0.0.1 --directory web
```

`npm run build` обновляет включённый в репозиторий bundle. Исходники интерфейса находятся в `web/react/`; API-адаптер, учебное хранилище и строгая проверка сдачи используют общие модули `web/*.mjs`.

Учебный режим содержит только вымышленные диалоги. Его оценки не выдаются за результат AI, а звук представляет собой созданный локально сигнал. Импорт DEV в этом режиме ничего не скачивает. Версии чек-листа, учебные задания и апелляции сохраняются в localStorage браузера; активное задание восстанавливается из sessionStorage при перезагрузке вкладки. Не использовать учебный режим для измерения точности модели.

Языки RU / EN / KK переключаются без перезагрузки страницы. Активные черновики чек-листа и решения апелляции, выбранные файлы выгрузки и подготовленный результат сохраняются при переключении языка и обычных переходах между разделами. Перезагрузка браузера не восстанавливает несохранённые черновики и выбранные файлы. Исходные тексты диалогов, комментарии и ответы модели автоматически не переводятся.

## Рабочие сценарии

- **Повтор ошибок:** статус «Ошибка оценки» и кнопка «Повторить ошибочные» работают в текущей выборке с учётом поиска, языка и канала. Перед запуском требуется подтверждение; клиент заново читает статусы, а сервер атомарно отклоняет устаревший запрос с HTTP 409. Успешные и ожидающие оценки сохраняются.
- **Аналитика:** отдельный раздел показывает последние сохранённые оценки по точной версии чек-листа и языку. Потери считаются по переданным сервером баллам; N/A и непроверенные ответы исключены из знаменателя, грубые ошибки считаются отдельно. Средний балл включает только полные оценки. Ошибки чтения и несовместимые снимки явно отмечаются. Новая оценка не запускается; mock-результаты помечены учебными.
- **История оценок:** в карточке диалога можно открыть прежний запуск с его моделью, временем, баллом и снимком чек-листа. Прямая ссылка и отчёт сохраняют выбранный запуск после перезагрузки. История содержит сохранённые запуски, а не журнал каждой правки апелляции.
- **Сравнение оценок:** внутри истории выберите два завершённых запуска одной версии чек-листа и нажмите «Сравнить оценки». Сохранённые ответы, баллы, обоснования и доказательства показываются рядом; фильтр «Только изменения» оставляет изменённые критерии. Различия доказательств и объяснений учитываются даже при одинаковом ответе. Для неполных оценок разница итогов не показывается. Сравнение выполняет только GET-запросы, проверяет принадлежность диалогу и совместимость сохранённых правил, не пересчитывает и не меняет результаты. Служебные ID апелляций и даты решений сами по себе не считаются изменением критерия.
- **Требует внимания:** единая очередь диалогов с грубыми нарушениями, пометкой `needs_review` или открытой апелляцией. В очереди сначала показываются более приоритетные нарушения; язык, канал, поиск и причина проверки работают совместно. Закрытая апелляция сама по себе не оставляет диалог в очереди.
- **Сводка:** по умолчанию отражает текущую выборку, включая очередь и фильтры. Переключатель «Охват сводки» позволяет посмотреть весь набор. Нулевой балл учитывается, отсутствие рассчитанного балла не превращается в ноль. Неполная оценка отмечается отдельно и не считается окончательным результатом; отсутствие ответа не превращается в N/A. Полностью неприменимый чек-лист с итогом `null` допустим.
- **Апелляция:** форма решения показывает исходные реплики, соседний контекст, правило и объяснение. Ссылки на реплики проверяются. Для звонка можно загрузить свежую запись и перейти к фрагменту. Черновик решения сохраняется в памяти вкладки при переходе к полному диалогу; «Отмена» удаляет его. После перезагрузки несохранённый черновик не восстанавливается, браузер предупреждает о несохранённых изменениях.
- **Версии чек-листа:** перед отправкой на сервер показывается «Было / Станет» для изменённых настроек, добавленных и удалённых критериев. Отмена возвращает к редактированию. Неизменённый чек-лист не создаёт новую версию. Закрытие окна блокируется только на время сохранения, чтобы ответ медленного запроса не затёр новые правки.
- **Отчёт:** в карточке оценённого диалога открыть «Отчёт», затем «Печать / PDF». Печатаются исходный и финальный баллы, критерии, доказательства с контекстом, решения по этой оценке и полный транскрипт, включая клиента, бота и систему. Полный транскрипт печатается независимо от раскрытия блока на экране. Неполная оценка получает предупреждение и заголовок «Предварительный балл». Новый вызов AI не выполняется. В диалоге печати браузера выбрать сохранение в PDF. Аудиоадреса и ссылки с данными доступа в отчёт не включаются; учебные результаты явно помечены. Правила другой версии чек-листа не подставляются.

## Выгрузка для сдачи

Раздел **Выгрузка** (`#submission`) работает и без сервера CQA. Название команды по умолчанию — `seeusoon`, задаётся в `config.js` через `teamName`. Нужны исходный JSON набора организаторов и сохранённые оценки из файлов оценщика или API команды. Проверка охватывает весь DEV/PROD независимо от фильтров списка диалогов. В JSON попадают только поля схемы 1.0; номера исходных реплик преобразуются с 0 на 1, а ошибки обработки сохраняются как `status: "error"` с `score: null`.

Учебные и mock-оценки блокируются, в том числе внутри ошибочных записей; незавершённая ручная проверка и несовместимый чек-лист не обходятся. По умолчанию выбираются исходные ответы AI. Равные `original_answer` и текущие ответы в исходном DTO сервера без ручного решения не означают пересмотр. После настоящего решения проверяющего для исходной версии требуется полный `original_criteria`; иначе нужно явно выбрать финальную версию. Если оценщик не передал итог, браузер считает его по фиксированным весам приложения к регламенту; если итог передан, он должен совпасть. Это преобразование готовых ответов, новый вызов модели не выполняется. Для предупреждений и записей с ошибкой требуется отдельное подтверждение перед скачиванием.

Кнопка скачивает `results.json`; его нужно сохранить в `results/dev/` или `results/prod/`, проверить командой `node web/check-submission.mjs` и затем сделать commit/push. Подробности и команды — в [results/README.md](../results/README.md). Файлы с настоящими оценками пока не созданы.

## Подключение сервера

В `config.js`:

```js
window.CQA_CONFIG = { apiBase: '/api', demo: false };
```

Настройки также доступны через кнопку шестерёнки в верхней панели. Настройки браузера имеют приоритет над файлом, а `?demo=1` явно включает учебный режим. При переключении источника через настройки этот параметр удаляется.

Сервер может раздавать `web/` и `/api` с одного адреса. Для отдельного порта указать, например, `http://127.0.0.1:8000/api` и разрешить конкретный origin интерфейса в CORS сервера. API-ключи и подписанный адрес организаторов должны оставаться на сервере. Интерфейс их не запрашивает. Неверный адрес или ответ API блокирует работу с серверными данными; учебный режим автоматически не включается. Включить его можно только явно. При смене источника интерфейс запрашивает подтверждение потери несохранённых правок чек-листа или решения апелляции.

## Контракт с сервером

Маршруты соответствуют `reports/задачи.md`; вся работа с ними находится в `api.mjs`. Поддерживаются прямые JSON-объекты и обёртка `{data: ...}`. Списки могут быть массивами или объектами с `dialogs`, `checklists`, `appeals`, `items` либо `records`.

- Строка списка диалогов: `conversation_id`, `channel`, `language`, необязательные `title`, `transcript`, `evaluation_id`, `status`, `total`, `gross_error`, `needs_review`. Для корректной очереди сервер должен передавать `needs_review` в списке, если какой-либо ответ требует ручной проверки. Карточка возвращает полный `transcript` с `timestamp`, `speaker`, `text`.
- Загрузка транскрипта: `POST /dialogs/upload`, `multipart/form-data`, поле `file`. UI допускает JSON до 5 МБ. Учебный адаптер принимает одну запись, массив или `{data:{records:[]}}`.
- `POST /evaluations` принимает `{conversation_ids, checklist_id, only_failed?:boolean}` и возвращает `{id}` задания. При `only_failed:true` все выбранные диалоги должны иметь последнюю оценку со статусом `error`; иначе HTTP 409 без создания задания. Перед запуском требуется явное подтверждение, особенно для платного AI API. Повторный запуск блокируется, пока текущее задание отслеживается.
- `GET /dialogs/{id}/evaluations` возвращает историю запусков: `id`, `status`, `checklist_id`, `checklist_version`, `model`, `created_at`, `total`, `original_total`, `gross_error`, `complete`, `needs_review_count`. Для открытия используется `GET /evaluations/{id}` с исходным снимком чек-листа.
- `GET /jobs/{id}`: `{id,status,completed,total,evaluation_ids,failed,errors}`. При частичном провале завершённого задания интерфейс оставляет предупреждение и предлагает обновить диалоги. Статусы: `queued`, `running`, `completed`, `failed`. В UI ограничено время опроса, есть повтор проверки без создания нового задания.
- Оценка: `id`, `conversation_id`, `checklist_id`, `checklist_version`, `total`, `gross_error`, `criteria`; рекомендован `checklist` со снимком конфигурации, чтобы старые результаты не отображались по изменённым правилам. При отсутствии точной версии интерфейс показывает предупреждение и не разрешает решение по критерию другой версии. `complete: false`, непустой `missing`, отсутствующий критерий или ответ означают неполную оценку. `original_total` и `criteria[].original_answer` показывают исходную оценку после пересмотра; равное текущему значение само по себе пересмотром не является. Для выгрузки исходной версии после ручного решения нужен полный `original_criteria`, включая исходные доказательства. Для отчёта используются `evaluated_at`, `model` и `sections`, если они переданы.
- Баллы критерия: предпочтительно `points` после перераспределения N/A, `effective_weight` как максимум, `weight` как базовый вес. При отсутствии `points` UI показывает переданный сервером `score`; он должен содержать баллы, а не долю от 0 до 1. Итог всегда берётся с сервера, реальное AI-решение браузер не вычисляет.
- Сохранение чек-листа: `POST /checklists`, полная конфигурация; ответ содержит сохранённые `id` и `version`. Список возвращает последнюю версию каждого ID. Новая версия не меняет уже выполненные оценки.
- Доказательства: `evidence:[{turn,quote}]`, индекс `turn` с нуля; пропуск действия: `checked_range:{from,to}`; N/A: `na_reason`. Текст выводится с экранированием HTML.
- `GET /dialogs/{id}/audio`: `{url,turn_offsets:{"0":0,"1":12.5}}`. Позиции в секундах вычисляет сервер с учётом пауз; UI отступает на 3 секунды назад. Также поддерживается поле `audio_url`. Автовоспроизведения нет, ссылку можно обновить.
- Апелляция: `POST /appeals` с `{evaluation_id,criterion_id,comment}`. Решение: `POST /appeals/{id}/decision` с `{answer,reason,status:"confirmed"|"changed"}`. Список апелляций возвращает `id`, `evaluation_id`, `criterion_id`, `comment`, `status`, `decision`; `conversation_id` и `criterion_title` необязательны.

Совместимость проверена со снимками сервера из `main` на коммитах `b6ca357` и `8a0e957`: настоящий FastAPI и SQLite запущены в отдельных временных копиях с mock-провайдером и вымышленными диалогами. Сервер включён в эту ветку: `python -m uvicorn app.server.main:app --host 127.0.0.1 --port 8000` (Python-окружение с зависимостями из корневого README). Он раздаёт API и текущий React-интерфейс с одного адреса. Эта проверка подтверждает работу интерфейса с API и сохранением в базе, но не проверяет качество реальной модели. Платный AI не вызывался, точность относительно Ground Truth не измерялась. Если сервер использует порт 8765, статическому предпросмотру нужно назначить другой порт.

## Проверка

```bash
npm run build
npm run typecheck
npm test
```

Восемь браузерных наборов Playwright MCP: `browser-smoke.js`, `browser-api.js`, `browser-security.js`, `browser-improvements.js`, `browser-submission.js`, `browser-react-workflows.js`, `browser-live-api.js` и `browser-connection.js`. Сценарии находятся в `tests/`; при работающем сервере вызвать `browser_run_code_unsafe` с `filename`, указывающим на нужный файл. Каждый сценарий создаёт отдельный браузерный контекст и закрывает его, не меняя пользовательский учебный пример. Окружение, результаты и границы проверки описаны в [QA.md](QA.md).

Проверены фильтры и пустая выдача; доказательства; подача и решение апелляции; сохранение после перезагрузки; новая версия чек-листа и дополнительный критерий; фоновая учебная оценка; аудио; загрузка JSON и отказ на некорректном JSON; экранирование HTML; ширины 320, 390, 768 и 1440; клавиатурный переход к содержимому; ошибка API без скрытой подмены данных. При ожидаемой ошибке API в статическом предпросмотре запросы `/api/*` получают HTTP 404.

`browser-api.js` перехватывает все запросы `/api/*` и хранит переданные записи в тестовом сервере: проверяет последующее чтение сохранённых чек-листов и апелляций, отсутствие второго POST оценки, восстановление задания при перезагрузке, остановку опроса при ошибке, HTTP 503 и неверный формат данных. Вызовов платной модели нет. `browser-security.js` проверяет отклонение HTML в повреждённом диапазоне доказательств с положительным контролем рабочего числового диапазона и скрытие повреждённой подписанной ссылки на аудио.

`browser-improvements.js` проверяет очередь внимания, выборку сводки, контекст внутри апелляции, сохранение черновика при переходе, сравнение и отмену сохранения чек-листа, печатный отчёт и аудиопереход. PDF для визуальной проверки сохраняется вне репозитория. `browser-api.js` дополнительно проверяет медленное сохранение и отказ от пересмотра с несовпадающим снимком чек-листа. Подробные результаты и границы проверки: `QA.md`.

`browser-submission.js` проверяет реальное скачивание JSON для полных DEV/PROD, чтение файлов без API, типы критериев и исходную нумерацию реплик, повторную проверку после изменения метаданных и замены файлов, отказы на дубли/пропуски/посторонние ID и mock-результаты, подтверждение предупреждений и сохранение ошибочных записей. Серверный сбор в этом наборе использует перехваченные GET; вызовы модели и внешняя отправка не выполняются.

`browser-react-workflows.js` проверяет рабочие сценарии React и сохранение активных черновиков при смене языка. `browser-connection.js` проверяет отказ при неверном API и явное переключение в учебный режим. `browser-live-api.js` проверяет интеграцию с настоящим FastAPI/SQLite из указанной временной копии и mock-провайдером. Эти проверки не являются замером точности AI.

Справка по используемым браузерным механизмам: [dialog](https://developer.mozilla.org/en-US/docs/Web/HTML/Reference/Elements/dialog), [Fetch API](https://developer.mozilla.org/en-US/docs/Web/API/Fetch_API/Using_Fetch).

`browser-analytics-regression.js` запускается с `tests/comparison_server.py` на порту 8767: проверяет среднее по настоящим DTO, грубые ошибки вне числового подсчёта, семантически одинаковые снимки с другим порядком JSON-полей и исключение неполных результатов. Запросы только GET, база временная, провайдер mock.
