# Интерфейс CQA

HTML, CSS и JavaScript без сборщика, npm-пакетов, внешних шрифтов и трекеров. Визуальный ориентир — предоставленные пользователем материалы Freedom Broker. Интерфейс обозначен как прототип команды. Палитра, компоненты и границы визуального слоя описаны в `../DESIGN.md`.

## Локальный запуск

Из корня репозитория:

```bash
python3 -m http.server 8765 --bind 127.0.0.1 --directory web
```

Открыть `http://127.0.0.1:8765/?demo=1` для учебного примера. Открытие `index.html` через `file://` не поддерживается: модулям JavaScript нужен HTTP.

Учебный режим содержит только вымышленные диалоги. Его оценки не выдаются за результат AI, а звук представляет собой созданный локально сигнал. Импорт DEV в этом режиме ничего не скачивает. Версии чек-листа, учебные задания и апелляции сохраняются в localStorage браузера; активное задание восстанавливается из sessionStorage при перезагрузке вкладки. Не использовать учебный режим для измерения точности модели.

## Подключение сервера

В `config.js`:

```js
window.CQA_CONFIG = { apiBase: '/api', demo: false };
```

Настройки также доступны через кнопку шестерёнки в верхней панели. Настройки браузера имеют приоритет над файлом, а `?demo=1` явно включает учебный режим. При переключении источника через настройки этот параметр удаляется.

Сервер может раздавать `web/` и `/api` с одного адреса. Для отдельного порта указать, например, `http://127.0.0.1:8000/api` и разрешить конкретный origin интерфейса в CORS сервера. API-ключи и подписанный адрес организаторов должны оставаться на сервере. Интерфейс их не запрашивает. При ошибке API учебный режим автоматически не включается.

## Контракт с сервером

Маршруты соответствуют `reports/задачи.md`; вся работа с ними находится в `api.mjs`. Поддерживаются прямые JSON-объекты и обёртка `{data: ...}`. Списки могут быть массивами или объектами с `dialogs`, `checklists`, `appeals`, `items` либо `records`.

- Строка списка диалогов: `conversation_id`, `channel`, `language`, необязательные `title`, `transcript`, `evaluation_id`, `status`, `total`, `gross_error`. Карточка возвращает полный `transcript` с `timestamp`, `speaker`, `text`.
- Загрузка транскрипта: `POST /dialogs/upload`, `multipart/form-data`, поле `file`. UI допускает JSON до 5 МБ. Учебный адаптер принимает одну запись, массив или `{data:{records:[]}}`.
- `POST /evaluations` принимает `{conversation_ids, checklist_id}` и возвращает `{id}` задания. Перед запуском требуется явное подтверждение, особенно для платного AI API. Повторный запуск блокируется, пока текущее задание отслеживается.
- `GET /jobs/{id}`: `{id,status,completed,total,evaluation_ids}`. Статусы: `queued`, `running`, `completed`, `failed`. В UI ограничено время опроса, есть повтор проверки без создания нового задания.
- Оценка: `id`, `conversation_id`, `checklist_id`, `checklist_version`, `total`, `gross_error`, `criteria`; рекомендован `checklist` со снимком конфигурации, чтобы старые результаты не отображались по изменённым правилам. `original_total` и `criteria[].original_answer` показывают исходную оценку после пересмотра.
- Баллы критерия: предпочтительно `points` после перераспределения N/A, `effective_weight` как максимум, `weight` как базовый вес. При отсутствии `points` UI показывает переданный сервером `score`; он должен содержать баллы, а не долю от 0 до 1. Итог всегда берётся с сервера, реальное AI-решение браузер не вычисляет.
- Сохранение чек-листа: `POST /checklists`, полная конфигурация; ответ содержит сохранённые `id` и `version`. Список возвращает последнюю версию каждого ID. Новая версия не меняет уже выполненные оценки.
- Доказательства: `evidence:[{turn,quote}]`, индекс `turn` с нуля; пропуск действия: `checked_range:{from,to}`; N/A: `na_reason`. Текст выводится с экранированием HTML.
- `GET /dialogs/{id}/audio`: `{url,turn_offsets:{"0":0,"1":12.5}}`. Позиции в секундах вычисляет сервер с учётом пауз; UI отступает на 3 секунды назад. Также поддерживается поле `audio_url`. Автовоспроизведения нет, ссылку можно обновить.
- Апелляция: `POST /appeals` с `{evaluation_id,criterion_id,comment}`. Решение: `POST /appeals/{id}/decision` с `{answer,reason,status:"confirmed"|"changed"}`. Список апелляций возвращает `id`, `evaluation_id`, `criterion_id`, `comment`, `status`, `decision`; `conversation_id` и `criterion_title` необязательны.

Это уточнения формата для подключения фронтенда. В репозитории на момент реализации сервера `app/server/` ещё нет; совместимость с живым сервером команды необходимо проверить после его появления.

## Проверка

```bash
node --test web/tests/*.test.mjs
node --check web/app.mjs
node --check web/result-view.mjs
node --check web/forms-preview.mjs
```

`result-view.test.mjs` проверяет отображение переданных баллов без пересчёта и мутации данных, группировку произвольных критериев, N/A, отдельную отметку грубой ошибки, экранирование цитат, корректные переходы и сравнение исходного результата с итоговым. Текущая визуальная доработка проверена тестами и статическим просмотром кода; повторная проверка в браузере ещё требуется, поскольку инструмент браузерного доступа был недоступен. Перечень ниже относится к проверке исходного интерфейса до этой доработки.

Браузерные сценарии Playwright MCP находятся в `tests/browser-smoke.js`, `tests/browser-api.js` и `tests/browser-security.js`. При работающем сервере на порту 8765 вызвать `browser_run_code_unsafe` с `filename`, указывающим на нужный файл. Каждый сценарий создаёт отдельный браузерный контекст и закрывает его, не меняя пользовательский учебный пример.

Проверены фильтры и пустая выдача; доказательства; подача и решение апелляции; сохранение после перезагрузки; новая версия чек-листа и дополнительный критерий; фоновая учебная оценка; аудио; загрузка JSON и отказ на некорректном JSON; экранирование HTML; ширины 320, 390, 768 и 1440; клавиатурный переход к содержимому; ошибка API без скрытой подмены данных. При ожидаемой ошибке API в статическом предпросмотре запросы `/api/*` получают HTTP 404.

`browser-api.js` перехватывает все запросы `/api/*` и хранит переданные записи в тестовом сервере: проверяет последующее чтение сохранённых чек-листов и апелляций, отсутствие второго POST оценки, восстановление задания при перезагрузке, остановку опроса при ошибке, HTTP 503 и неверный формат данных. Вызовов платной модели нет. `browser-security.js` проверяет отклонение HTML в повреждённом диапазоне доказательств с положительным контролем рабочего числового диапазона и скрытие повреждённой подписанной ссылки на аудио.

Справка по используемым браузерным механизмам: [dialog](https://developer.mozilla.org/en-US/docs/Web/HTML/Reference/Elements/dialog), [Fetch API](https://developer.mozilla.org/en-US/docs/Web/API/Fetch_API/Using_Fetch).
